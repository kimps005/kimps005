01한눈에 보기

문제
생성형 AI 세 종류(스토리·삽화·음성)를 엮는 서비스라, 모델 과부하·차단·출력 형식 오류가 시연 중에도 일어날 수 있었습니다. 그런데 API 라우트는 60초 안에 끝나야 했습니다.
해결
시간 예산 안에서 대체 모델을 순환 재시도하고, JSON 스키마 가드·Vision 주인공 검증·사전 생성 동화까지 이어지는 다단 Fallback을 설계했습니다. 저는 TTS 낭독, 읽기 화면, 로컬 4bit 이미지 서버를 맡았습니다.
결과
해커톤 대상(전체 1위). 8 GB 노트북 GPU에서 FLUX.2 4bit 로컬 서빙(생성 중 VRAM 약 6 GB)을 검증했습니다.

  4. VERIFYJSON 스키마 가드 · 주인공 Vision 검증GUARDRAIL 재시도 · Fallback

  • Gemini JSON Schema 응답을 타입 가드로 검증한 뒤 장면별 영어 imagePrompt로 FLUX.2 삽화를 만들고, 아이 그림의 주인공이 반영됐는지 Vision 모델로 다시 확인합니다.

04주요 기능 개발

제가 직접 설계·구현한 부분입니다.

01동화 낭독 (Azure Neural TTS)

  • 브라우저 → 서버 TTS 프록시 → Azure Speech 경로를 구현해 키를 클라이언트에 노출하지 않음
  • 사용자가 낭독 음성을 고를 수 있는 음성 선택 기능

02동화 읽기 화면

  • 장면 단위 페이지네이션과 전체화면 읽기 모드 구현

03FLUX.2 로컬 4bit 이미지 서버 (구현·검증)

  • 8 GB VRAM 노트북 GPU(RTX 5060 Laptop) 한 대에서 FLUX.2 Klein 4B를 돌리기 위해 커뮤니티 NF4 가중치 사용
  • 누락된 Qwen 텍스트 인코더는 공식 가중치를 로드 시점에 NF4로 양자화해 보완
  • VAE tiling, 512 px·4 step 고정, 모델 GPU 상주, CUDA OOM 시 캐시 정리 후 503 반환
  • 생성 중 VRAM 약 6 GB 점유를 확인한 뒤, 서비스 경로는 안정성을 위해 Cloudflare Workers AI로 유지

05기술적 의사결정

제약 조건 안에서 어떤 대안을 비교했고 왜 그 선택을 했는지 정리했습니다.

DECISION 01

고품질 모델 하나 대신, 빠른 경량 모델을 기본으로 두고 대체 모델을 순환 (팀 설계)

상황
API 라우트 최대 실행 60초. 상위 모델은 혼잡 시 수십 초가 걸리고, 기획 모델(gemini-2.5-flash)은 신규 사용자 차단
선택지
A. 상위 품질 모델 단일 호출
B. 2초대 응답 lite 모델 기본 + 과부하(503)·시간 초과 시 대체 모델 순환
결정
B. 시도당 20초·전체 45초 예산 안에서 최대 8회 모델 순환 재시도 (백오프 500 ms × n, 최대 2.5초), 남은 예산이 3초 미만이면 중단
효과
thinkingLevel LOW로 추론 시간을 줄이고, 60초 라우트 한도 안에서 응답 보장

DECISION 02

이미지 생성을 로컬 4bit로 서빙할 수 있는지 검증 (본인 구현)

상황
8 GB VRAM 노트북 GPU 한 대뿐인 환경
결정
FLUX.2 Klein 4B NF4 가중치 + 텍스트 인코더 로드 시점 NF4 양자화, VAE tiling, 512 px·4 step 고정
효과
생성 중 VRAM 약 6 GB로 구동 확인. 시연 안정성을 고려해 서비스 경로는 Cloudflare Workers AI 유지

01이미지 생성 서버가 일시적으로 실패할 때, 재시도가 과금 중복으로 이어질 수 있던 문제

삽화 생성이 실패하면 다시 요청해야 하지만, 무작정 재전송하면 유료 이미지가 중복 생성될 수 있었습니다.

원인

  • Cloudflare Workers AI의 429·5xx 일시 장애
  • 타임아웃·연결 끊김 요청은 서버에서 이미 생성 중일 수 있음

해결

  • 요청당 45초 타임아웃
  • 명시적 일시 거부(429·5xx)만 최대 2회 재시도, Retry-After가 5초를 넘으면 즉시 실패
  • 타임아웃·네트워크 오류는 재전송하지 않음
  • 안전 필터·쿼터·인증 오류를 에러 코드별로 구분해 사용자 메시지 분리

결과

  • 중복 과금 위험 없이 일시 장애 흡수

02AI가 아이 그림 속 주인공을 무시하거나, 스토리 JSON이 깨지던 문제

이미지 모델이 참조 그림을 무시하고 임의의 주인공을 그리거나, LLM 출력이 스키마와 맞지 않는 경우가 있었고, 시연 중 Gemini가 차단되기도 했습니다.

원인

  • 이미지 모델의 참조 그림 무시
  • LLM 출력 스키마 불일치
  • 외부 모델 차단·장애

해결

  • Gemini Vision으로 주인공 반영 여부 판별 (temperature 0, 10초 타임아웃, 검증기 장애 시 통과 처리)
  • 실패 시 1회 재생성 → 재실패 시 배경만 생성 후 원본 그림 합성 → 업스트림 장애 시 로컬 배경
  • 스토리 스키마 검증 실패 시 재시도, 최종 실패 시 사전 생성한 프리셋 동화(4종 × 7구간) 반환, 응답에 fallback 플래그 부착

결과

  • 프리셋 입력 기준, AI 전면 장애에서도 동화가 끝까지 이어짐

07회고 · 개선 방향

현재 한계

사전 생성 동화 Fallback은 프리셋·특정 키워드 입력에만 적용되어, 그 외 자유 입력은 AI가 전부 실패하면 500을 반환합니다. 생성 전 과정이 60초 동기 요청에 묶여 있습니다.

다음 단계

생성 요청을 비동기 작업 큐로 분리하고 작업 ID 기반 SSE로 진행 상태 스트리밍, 동일 입력의 스토리·TTS 결과 캐싱으로 Azure F0 한도(60초당 20건) 대응, 사용자별 이미지 생성 쿼터 적용
