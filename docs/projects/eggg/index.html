01한눈에 보기

문제
로컬 GPU 한 대로 45초 라운드 안에 AI 그림을 만들어 모든 플레이어에게 보여줘야 했는데, 생성된 그림이 일부 플레이어 화면에 나타나지 않았습니다.
해결
SD-Turbo 1-step 생성으로 지연을 줄이고, 이미지를 Base64로 DB에 넣던 방식을 ‘파일 저장 후 URL만 기록’으로 바꿨습니다.
결과
DB 기록 페이로드를 수백 KB~수 MB에서 약 70 B로 줄여 Vercel 413 오류를 해소했고, 라운드 종료 시 정답 메시지 중복(2회)을 1회로 바로잡았습니다.

04주요 기능 개발

제가 직접 설계·구현한 부분입니다.

01SD-Turbo 이미지 생성 백엔드 (FastAPI)

  • SD-Turbo 512×512, 기본 1 step 실시간 생성
  • CUDA fp16 + attention slicing으로 VRAM 약 2 GB 점유
  • CUDA 커널 호환성 테스트 실패 시 CPU fp32로 자동 전환, 모델 로드는 별도 스레드에서 실행해 이벤트 루프 블로킹 방지

02AI 생성 모드 Next.js 포팅

  • AI 생성 모드를 Next.js로 옮기고 내부 API 라우트를 통해 Tunnel 경유 GPU 서버로 중계
  • 방 단위 aiStatus ‘generating’ 가드로 중복 생성 요청 차단, 실패 시 idle 복귀 및 시스템 메시지 안내
  • 연속 입력 Debounce 700 ms

03게임 상태 동기화 수정

  • 타이머 만료 시 이벤트가 두 채널로 중복 발송되던 문제를 단일 채널로 통합 (아래 트러블슈팅 2)
  • 최종 라운드 종료 시 최고 득점자에게 방장을 결정론적으로 위임 (score DESC, nickname ASC)

상황

선택지

B. SD-Turbo 1~4 step 저지연 생성

효과

상황

효과

06트러블슈팅

문제 → 원인 → 해결 → 결과 순서로 정리했습니다.

01AI가 그린 그림이 일부 플레이어 화면에 나타나지 않던 문제

AI 모드에서 이미지를 생성해도 다른 플레이어에게 동기화되지 않았습니다.

원인

  • 수백 KB~수 MB의 Base64 이미지를 DB 컬럼에 직접 기록
  • Vercel 서버리스 요청 바디 제한 초과(HTTP 413)로 ai_image_url 갱신 실패

해결

  • AI 백엔드가 이미지를 정적 파일로 저장한 뒤 URL만 반환하도록 응답 포맷 변경
  • 프론트 재배포 없이 백엔드 단독으로 적용

결과

  • DB 기록 페이로드 수백 KB~수 MB → 약 70 B
  • HTTP 413 → 정상 갱신

02라운드가 끝날 때 정답 메시지가 두 번 뜨고, 정답 처리가 롤백되던 문제

타이머가 끝나는 순간 같은 이벤트가 중복으로 처리되며 서버 오류까지 이어졌습니다.

원인

  • 타이머 만료 시 WS 브로드캐스트와 DB 기록으로 이중 발송
  • React 인터벌 재생성으로 방장 클라이언트가 reveal-answer API를 2회 이상 호출
  • SQL 바인딩 파라미터 누락으로 500 → 정답 처리 롤백

해결

  • 정답 공개 메시지를 DB Polling 단일 채널로 통합
  • timerEndTriggeredRef 게이트로 첫 호출 후 잠그고 라운드 변경 시 해제
  • 서버 timerBlocker 배리어로 중복 타이머 실행 차단, 누락 파라미터 보완

결과

  • 라운드 종료 정답 메시지 2회 → 1회

07회고 · 개선 방향

현재 한계

방 상태가 ws 프로세스 하나의 메모리에 있고, 이미지 추론이 Tunnel 너머 로컬 GPU 한 대에 몰려 있습니다. 동시 방이 늘면 생성 대기가 생기고 프로세스 재시작 시 진행 상태가 사라집니다.

다음 단계

Redis Pub/Sub으로 룸 상태를 공유해 ws 서버 수평 확장, Polling을 없애고 WebSocket 단일 채널화, GPU 추론 큐·배치 처리 도입, 생성 이미지 오브젝트 스토리지 이전
